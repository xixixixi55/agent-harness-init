# Portable complete Harness iteration

## Outcomes
Implemented a complete provider-neutral Harness architecture with risk routing, OpenSpec-compatible change artifacts, executable lifecycle protocols, deterministic gates, strict ownership, review separation, spec sync, and npm 0.2.0 release preparation.

## Problems
Independent review exposed subtle ownership adoption, incomplete structural parsing, guessed commands, provider completeness, placeholder evidence, and Skill validity risks. Each was reproduced and covered by regression tests.

## Lessons
Portable governance must validate ownership and evidence structure as strictly as implementation behavior. Shared semantics belong in one provider-neutral protocol, while adapters remain thin links.

## Project Harness Updates
Added strict frozen-candidate review, living-spec sync, iteration learning, and release evidence to this repository's own OpenSpec change.

## Template Candidates
None beyond the explicitly requested portable architecture implemented by this change.
